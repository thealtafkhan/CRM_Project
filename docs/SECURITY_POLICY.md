# APPLICATION SECURITY POLICY — AcxiomCRM

## 1. Security Baseline & Guiding Principles
AcxiomCRM is engineered with a **Defense-in-Depth** security architecture, adhering to OWASP Top 10 web application security principles. Security checks are enforced server-side; client-side rules exist exclusively to enrich user experience and provide immediate feedback.

---

## 2. Core Security Controls

### 2.1 Cryptographic Password Security
- Passwords are never stored or logged in plaintext.
- Passwords hashed using ASP.NET Core Identity's PBKDF2 with HMAC-SHA256, 100,000 iterations and 128-bit cryptographically random salt.
- Password policy enforces:
  - Minimum length: 8 characters.
  - Minimum 1 uppercase letter (`[A-Z]`).
  - Minimum 1 lowercase letter (`[a-z]`).
  - Minimum 1 decimal digit (`[0-9]`).
  - Minimum 1 non-alphanumeric special character (`[!@#$%^&*()_+\-=\[\]{};':"\\|,.<>\/?]`).

### 2.2 Account Lockout Defense
- Consecutive failed login attempts increment `FailedAccessCount`.
- Exceeding 5 failed attempts within a 10-minute window triggers account lockout:
  - Account locked for 15 minutes (`LockoutEnd = DateTimeOffset.UtcNow.AddMinutes(15)`).
  - Generic message displayed: *"Account is locked. Please try again later or contact your administrator."*
  - Lockout event written to `AuditLog`.
  - Authorized Administrators can manually clear lockout flags.

### 2.3 Cross-Site Request Forgery (CSRF) Mitigation
- Anti-forgery tokens (`__RequestVerificationToken`) automatically injected into all Razor forms.
- Global filter `AutoValidateAntiforgeryTokenAttribute` registered across MVC controllers.
- State-changing API endpoints authenticate via JWT Bearer headers, which are inherently immune to ambient cookie CSRF attacks.

### 2.4 SQL Injection Prevention
- 100% of database operations execute through Entity Framework Core parameterized LINQ queries.
- String concatenation inside raw SQL queries (`FromSqlRaw($"SELECT ... {userInput}")`) is strictly prohibited by coding standards and CI linter rules.

### 2.5 Cross-Site Scripting (XSS) Prevention
- Razor automatically HTML-encodes all dynamic output (`@Model.CustomerName`).
- Raw HTML rendering (`@Html.Raw(...)`) is strictly forbidden on user-submitted data.

### 2.6 Data Protection & Secret Management
- Database credentials and JWT signing keys are stored exclusively in Environment Variables or ASP.NET Core Secret Manager (`dotnet user-secrets`).
- Zero hardcoded connection strings or secrets committed to source control.
- Logs generated by Serilog scrub sensitive keys (passwords, tokens, credit cards).
